# GEO policy: making anamata.ai legible to AI search

Taiga #343. This covers the machine-legible half only. Nothing here adds copy
or claims: every value is taken from data already in the repository.

## What is generated where

| Output | Source | Generated by |
|---|---|---|
| `/llms.txt` ([llmstxt.org](https://llmstxt.org) shape) | Every page under `src/pages` (title and meta description as rendered), plus the `insights` collection (frontmatter `title`, `description`) | `src/pages/llms.txt.ts`, at build time |
| One `application/ld+json` block per page | Organization (name, `https://anamata.ai/`, `public/anamata-ai-logo.svg`) on every page; WebSite on home; Article on each insight (`title`, `description`, `published`, `draftedBy`) | `src/layouts/Base.astro` with `src/lib/structured-data.mjs` |
| `/robots.txt` | `public/robots.txt`, copied as is | hand-written (policy below) |
| `/sitemap-index.xml` | All built pages | `@astrojs/sitemap` (unchanged) |

Nothing is hand-maintained: a new page or insight appears in `llms.txt` and
gets its JSON-LD on the next build. Redirect stubs (`/approach`, `/anna`) and
`404` are left out. JSON-LD escapes `<` as `<`, so no frontmatter string
can close the script element. The Article author is `draftedBy` as a plain
name, with no `Person` type: the drafter is an AI system, and no human identity
is invented. No `aggregateRating`, no `offers`.

`tests/geo.test.mjs` checks all of this against `dist/`, including a clean
fixture build that adds a page and a nested insight.

## Crawler policy

AI search and training crawlers are **allowed**, unchanged behaviour: the
wildcard group already allowed them. `public/robots.txt` now names GPTBot,
OAI-SearchBot, ClaudeBot, Claude-SearchBot, PerplexityBot, Google-Extended and
Applebot-Extended explicitly so the decision is written down. Recorded
2026-10-20, pending Ezra/Bas. Flipping it is a one-file change: replace a
group's `Allow: /` with `Disallow: /`.
